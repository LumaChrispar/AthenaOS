# MEM-001: Project Memory System

**Document ID:** MEM-001  
**Version:** 1.0  
**Status:** Locked  

---

## 1. Purpose
Athena OS agents (employees) have limited contextual windows. The Project Memory System acts as the "long-term memory" for a specific book during its active development cycle, preventing hallucinations, continuity errors, and character drift.

## 2. Memory Tiers

### Tier 1: The Project Bible (Static Context)
The absolute source of truth. Read-only for drafting agents.
- **Contents:** Finalized Literary Architecture (WF-001), Character Dossiers, World Rules.
- **Maintenance:** Managed solely by the Continuity Keeper (EMP-008).

### Tier 2: The Working Buffer (Dynamic Context)
The active memory for the current chapter/sequence being written.
- **Contents:** The specific beat sheet for the current chapter, the text of the immediately preceding chapter, and active subplots.
- **Maintenance:** Updated dynamically by the pipeline as chapters are completed.

### Tier 3: The Revision State (Delta Context)
The memory of what needs to be changed.
- **Contents:** QA Scorecards, Editorial Feedback, and the specific "Delta" (the difference between the current draft and the desired state).
- **Maintenance:** Generated by the QA Division, consumed and cleared by the Story Division upon successful revision.

## 3. Retrieval Protocols
- **Before Drafting:** An agent must query Tier 1 (Project Bible) for character constraints before generating prose.
- **During Drafting:** An agent maintains Tier 2 in its active context window to ensure flow from the previous scene.
- **During Revision:** An agent loads Tier 3 alongside the draft to execute specific requested changes without altering unaffected elements.

## 4. Archival
Upon publication (Phase 14), the Project Memory is frozen. Relevant successes or failures are abstracted and pushed to the Organizational Memory (MEM-002), and the specific Project Memory is archived for potential sequel generation.

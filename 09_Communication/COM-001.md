# COM-001: Structured Report Protocol

**Document ID:** COM-001  
**Version:** 1.0  
**Status:** Locked  

---

## 1. Purpose
To eliminate ambiguity, ensure traceability, and enforce logical rigor in all inter-departmental and inter-employee communication within Athena Publishing OS. Casual conversation is strictly prohibited in official pipelines.

## 2. The Standard Report Format

Every official communication (handoffs, rejections, approvals, proposals) must use the following JSON-compatible markdown structure:

### 1. Objective
A one-sentence summary of what this report is meant to achieve (e.g., "Requesting approval for the Act I Beat Sheet").

### 2. Context
The necessary background information (e.g., "This beat sheet is for Project X, a sci-fi thriller. It incorporates the CEO's notes on pacing").

### 3. Analysis / Findings
The core data or reasoning. (e.g., "The pacing is maintained by a ticking clock introduced in Scene 3. The character flaw is challenged in Scene 7").

### 4. Decision / Action Taken
What exactly is being done or requested. (e.g., "Submitting for QA Validation").

### 5. Confidence Level
A percentage (0-100%) indicating how certain the agent is that the output meets Athena standards, followed by a brief reason.

### 6. Risks
Identified weaknesses or potential failure points. (e.g., "Risk: The transition in Chapter 4 may rely too heavily on exposition").

### 7. Dependencies / Blockers
What must happen before the next step can occur.

## 3. Usage Rules
- **No Null Fields:** If a section is not applicable, state "N/A" with a brief justification.
- **Machine Readability:** Reports must be formatted cleanly so they can be parsed by automated pipeline scripts.
- **Traceability:** Every report must reference the Document ID or Project ID it pertains to.

## 4. Example Use Case: Editorial Handoff
When the Developmental Editor (EMP-006) rejects a draft from the Literary Author (EMP-005), the Editor must generate a COM-001 report detailing the exact structural failures in the Analysis section, and the required fixes in the Decision section. The Author must then reply with a COM-001 report detailing how the fixes were implemented.
